# 独立十风格 Pages、局域网自动更新与同步总开关设计

## 状态

- 设计日期：2026-08-07
- 目标版本：v0.7.0
- 用户已确认：独立页面方案
- 本规格取代 `2026-08-03-github-pages-ten-theme-motion-design.md` 中“共享 DOM + `data-theme`”的实现方案。
- 本规格延续 `2026-08-04-github-pages-apple-standalone-design.md` 与 `2026-08-05-windows-companion-sync-motion-design.md` 的独立 Apple 页面、Windows 伴侣和同步安全边界。

## 目标

本阶段同时完成四个用户结果：

1. 修复 Apple 页面在白色、黑色章节之间整屏突变的问题，让单个页面内部保持统一材质和连续背景。
2. 保留 Apple 页面作为第三套风格，并新增九个结构、内容顺序、布局、交互和动效均不同的独立页面。十套页面不能由共享 DOM 换色实现。
3. Android 在电脑同步开启且存在局域网服务器时自动查询电脑中的 APK，比较当前版本、局域网版本和 GitHub 版本，并在设置页显示可用更新及来源。
4. 电脑同步总开关关闭后立即停止 REST、WebSocket、重连、UDP 发现、配对和局域网更新查询，同时保留手机本地数据、服务器配置、配对令牌和待同步队列。

## 非目标

- 不静默下载或安装 APK。Android 系统仍负责安装确认与未知来源权限。
- 不实现 Windows 伴侣自身的自动更新。
- 不将十套页面合并为运行时 SPA，也不引入前端框架、动画库、外部字体或静态站点生成器。
- 不恢复旧截图型 Apple 页面。十套页面中的产品界面均使用 HTML/CSS 原生绘制；应用图标可以作为真实品牌资产使用。
- 不承诺在电脑同步关闭时进行任何局域网更新检查。关闭状态只允许 GitHub 手动检查。

## 总体架构

采用“十个独立静态页面 + 小范围共享事实与无视觉行为”的结构。

```text
docs/
  index.html                    # 03 Apple，根路径与 canonical 页面
  styles.css
  app.js
  styles/
    shared/
      reset.css                 # 最小 reset、焦点、无障碍与降级
      style-switcher.css        # 固定尺寸的风格导航基础
      style-switcher.js         # 跨文档切换、键盘行为、目标背景遮罩
      release-data.js           # 版本、大小、SHA-256、下载链接
    ancient/                    # 01 古风
      index.html
      style.css
      app.js
    cyber/                      # 02 赛博朋克
    terminal/                   # 04 终端
    government/                 # 05 政府严肃型
    sprint/                     # 06 冲刺仪表
    bauhaus/                    # 07 包豪斯
    stationery/                 # 08 日系文具
    blueprint/                  # 09 科研蓝图
    newspaper/                  # 10 墨水报刊
```

每个风格目录都必须拥有独立 `index.html`、主布局 CSS 和交互脚本。共享目录只能承载以下内容：

- release 事实：版本、平台要求、文件名、大小、SHA-256、下载 URL；
- 风格切换器的无障碍和跨文档导航；
- reset、焦点样式、reduced-motion 与无 JavaScript 降级；
- 与视觉无关且页面主动选用的复制校验值工具。

不得共享 hero、章节 DOM、卡片结构、内容顺序或整页布局组件。旧 `themes.css` 只能作为 token 参考，不能恢复为生产样式表。

## 十套独立信息架构

### 01 古风：策论长卷

- 首屏是纵向题签、产品名和“今日功课”摘要，不使用现代居中 hero。
- 主体按“定课、入静、温故、案头伴侣、版本落款”展开，使用长卷分栏、细墨线和边批。
- 轻交互是展开功课条目与切换背诵批注。
- 下载区表现为卷尾落款与附件清单，不使用现代下载卡片。
- 页面以宣纸白、墨黑、石青和少量朱红为连续浅色体系。

### 02 赛博朋克：夜行考场

- 首屏是非对称任务控制台，品牌、当前版本和连接状态分处不同网格。
- 主体按“任务遥测、专注能源、记忆缓存、局域网雷达、更新信号”排列。
- 轻交互是局域网扫描雷达和数据模块聚焦，不使用循环闪烁。
- 下载区是可执行载荷清单，Android 与 Windows 分为两条传输通道。
- 页面始终维持碳黑底和电青、品红、警示黄的暗色体系，避免暗到亮整屏跳变。

### 03 Apple：纯净聚焦

- 保留当前七个产品场景和任务、计时、翻卡、同步演示。
- 移除全屏黑色专注章节与黑色下载章节。专注计时器改为浅色章节中的黑色产品舞台，下载区改为冷灰浅色收束。
- 场景背景限制在 `#ffffff`、`#f5f5f7`、`#eef3f8` 等相邻亮度，背景淡化只承担轻微材质变化。
- Windows 和手机界面继续使用原生 DOM/CSS，不加载截图。

### 04 终端：执行控制台

- 首屏直接显示 `kgc status` 与今日任务输出，不使用营销文案结构。
- 内容是一条可读的命令会话：`plan`、`focus`、`drill`、`sync`、`update`、`install`。
- 用户通过命令按钮切换输出面板，键盘焦点与屏幕阅读器状态同步。
- 更新提示模拟包管理器结果，明确显示 `local-network` 或 `github` 来源。
- 页面始终保持终端黑底、磷光绿与琥珀黄，不做逐字打字等待动画。

### 05 政府严肃型：产品资料公报

- 页面顶部使用文件编号、发布日期、产品名称和摘要，不使用英雄插图。
- 内容按“适用范围、核心能力、数据管理、安装办法、附件下载”组织为正式文档和表格。
- 版本、系统要求和 SHA-256 前置显示，下载作为附件一、附件二。
- 轻交互只用于展开技术说明和复制校验值。
- 页面明确标注“产品资料页”，不使用国徽、印章、机关名称或政府背书暗示。

### 06 冲刺仪表：专注执行

- 首屏由大号完成率、连续天数和 25:00 计时读数组成，品牌作为运动成绩板标题。
- 内容顺序为“今日目标、计时分段、背诵命中率、电脑接力、立即下载”。
- 轻交互是计时启动、分段记录与目标勾选。
- 下载区表现为终点成绩单，不使用与 Apple 相同的双平台卡片。
- 石墨、冷白、信号黄、薄荷绿与珊瑚红保持高能但不使用渐变。

### 07 包豪斯：结构训练

- 首屏使用不对称红、蓝、黄矩形和超大编号建立品牌，不使用圆形装饰球。
- 功能内容被拆成不同尺寸、不同轨道的几何模块，阅读顺序仍由语义 DOM 保证。
- 轻交互是模块沿网格短距离归位和任务状态切换。
- Windows、同步和下载各占独立版面，不能复用前三套页面的构图。
- 动效只使用 transform、opacity 和受控裁切。

### 08 日系文具：每日手账

- 首屏是日期页签和今日清单，产品名像手账栏目名而非 hero 标题。
- 内容按一天时间线组织：晨读、做题、专注、复盘、电脑备份。
- 轻交互是勾选、页签切换和背诵便签翻页。
- 更新与下载位于“工具袋”页签，版本信息像文具标签但保持清晰可复制。
- 清白、铅笔灰、群青、番茄红和薄荷绿构成稳定浅色页面。

### 09 科研蓝图：学习实验室

- 首屏是产品组件总图，使用坐标、尺寸线和模块编号解释 Android 与 Windows 的关系。
- 内容按“输入、计时、记忆、同步总线、版本检测”展开。
- 局域网更新使用真实数据流图：发现服务器、读取版本、比较、显示更新、用户确认安装。
- 轻交互是切换图层标注和查看模块剖面。
- 工程白底为主，钴蓝、深墨、信号橙和少量荧光绿承担状态。

### 10 墨水报刊：备考日报

- 首屏是报头、日期、主标题与当日导语，产品功能以新闻版面呈现。
- 主体包含今日头条、专注专栏、背诵问答、电脑版面和版本公告。
- 轻交互是展开专栏摘要与切换问答，不模拟旧报纸噪点遮挡内容。
- 下载信息位于末版“发行公告”，使用分栏而不是卡片。
- 新闻纸白、浓墨黑、冷灰、报刊红和编辑蓝保持连续浅色体系。

## 风格导航与跨文档转场

### 导航

- 十套页面都提供相同语义的原生 `<details>` 风格导航，固定在视口边缘但不遮挡正文。
- `<summary>` 显示当前编号与名称；展开后显示十个真实链接。当前项使用 `aria-current="page"`。
- 链接访问根路径 Apple 页面或 `/styles/<slug>/`。无 JavaScript 时仍可正常切换。
- 切换总是进入目标页面首屏。不同页面内容顺序不同，不伪造跨页面章节位置映射。

### 无闪屏切换

- 支持的浏览器使用同源跨文档 View Transition。
- 每个风格链接声明目标页面基础背景色。点击后，源页面在 180 ms 内由同色遮罩覆盖，再执行导航；目标文档的内联首帧背景与遮罩完全一致。
- 目标页面内容使用 520 ms 进入，整体 easing 为 `cubic-bezier(0.22, 1, 0.36, 1)`。
- 不支持 View Transition 时仍先完成遮罩再导航，避免浏览器默认白屏。
- 快速连续点击只接受最后一次目标，不积压动画。
- `prefers-reduced-motion: reduce` 下取消位移和裁切，但保留 80 ms 颜色遮罩以防白屏；内容立即可读。

### 页面内部动效

- 控件反馈：180 ms。
- 背景与材质过渡：520 ms。
- 章节内容交接：680 ms。
- 高频动画仅修改 transform 和 opacity；不使用 `transition: all`、大面积 filter 或持续循环动画。
- 页面自然滚动，不使用滚轮劫持、强制翻页或移动端 pinned 空白区。

## Apple 页面背景突变修复

当前整屏颜色顺序包含白、黑、蓝灰、黑，并由离散场景状态选择固定背景，因此高对比章节会突变。本阶段采用以下修复：

1. Apple 页面所有 section 的基础背景保持在相邻浅色范围。
2. 黑色只作为计时器产品舞台和局部按钮材质，不再成为整屏 section 背景。
3. 下载终章使用浅灰背景和深色局部下载面板，不再整屏变黑。
4. 双背景层继续交叉淡化，但只在低对比颜色间工作。
5. 无 JavaScript与 reduced-motion 路径直接显示连续浅色 section，不出现白黑硬边界。
6. 场景状态仍保持唯一 current、前后 prev/next；快速滚动不排队。

## 局域网自动版本匹配

### 版本规则

- v0.7.0 是本阶段统一版本。Android `versionName`、`versionCode`、三个 `package.json`、Pages release 数据、APK 文件名和 Windows 安装器文件名必须一致。
- 服务端只接受 `kaogong-checkin-vX.Y.Z.apk`。
- 版本比较使用三段数值语义版本；高版本获胜，同版本优先局域网。
- 桌面 UI、二维码、`/api/update/latest` 和 `/updates/:file` 必须引用同一个服务端 APK 解析结果，不能再由桌面端按修改时间选择任意 `.apk`。

### 自动检查触发点

在以下条件满足时自动检查：

- 电脑同步总开关开启；
- 已配置或刚选中一个局域网服务器；
- 设置页首次进入、配对成功、服务器 URL 改变、同步从关闭切为开启，或连接恢复在线。

触发后等待 400 ms 稳定期并合并重复请求。同一服务器、同一应用版本和同一会话内，不因重复状态更新无限检查；用户仍可点击“检查更新”强制刷新。

### 请求与显示

1. 同时请求局域网 `/api/update/latest` 与 GitHub 最新 Release。
2. 任一来源成功即可比较；两者都失败才显示错误。
3. 若最高版本高于当前版本，设置页自动显示版本、来源、说明与下载按钮。
4. 若没有更高版本，显示“已是最新版本”；自动取消不显示错误闪烁。
5. 局域网下载失败时，可降级到不低于该版本的 GitHub APK。
6. 自动检查不自动开始下载；下载完成后仍由用户点击安装并经过 Android 系统确认。

### 取消与安全边界

- 更新协调器拥有独立 generation 与 `AbortController`。
- 同步关闭、服务器改变、设置页卸载或新的强制检查开始时，立即取消旧 LAN 请求。
- `fetchLatestLanRelease()` 在关闭态直接拒绝，不允许绕过总开关。
- 关闭后返回的旧结果不得更新界面。
- GitHub 手动检查可以在关闭同步时运行，但自动检查不得以 GitHub 请求为理由启动局域网活动。

### 服务发现元数据

- UDP 广播增加真实 `protocolVersion`、`apkAvailable` 与 `apkVersion`。
- 客户端不再把 v2 服务器错误显示为协议 v1。
- APK 元数据和下载接口继续公开，仅在可信局域网使用；同步状态 API 仍要求客户端令牌。

## 电脑同步总开关

### 开启

- 初始化本地状态后启动 UDP 发现和同步生命周期。
- 用户选中服务器并完成六位码配对后启动 REST 快照与 WebSocket。
- 开启本身不自动覆盖电脑或手机数据，也不自动下载安装更新。

### 关闭

关闭操作必须作为一个串行生命周期完成：

1. 先持久化关闭偏好并递增总 generation。
2. 取消局域网更新检查、配对、快照和覆盖请求。
3. 清除重连 timer，解绑并关闭 WebSocket。
4. 停止 UDP 监听、关闭 socket、清除扫描 timer 和发现结果。
5. 将界面状态改为 local，禁用扫描、配对和 LAN 更新操作。

关闭时保留：

- 本地应用状态；
- 待同步队列及稳定 mutation id；
- 已配置服务器 URL、服务器 id 和配对令牌；
- 已下载但尚未安装的 APK 状态。

重新开启后必须由新的 generation 启动，不允许旧回调复活。直接调用 `pairComputerServer()`、`fetchLatestLanRelease()` 等公开模块入口也必须检查总开关。

## 错误处理

- 局域网服务器没有 APK：视为 LAN 来源不可用，继续使用 GitHub 结果。
- 局域网超时：3 秒后取消 LAN 分支，不阻塞 GitHub 结果。
- 同步关闭导致取消：静默回到本地状态，不显示“检查失败”。
- GitHub 失败但 LAN 有更新：正常显示 LAN 更新。
- 两个来源均失败：保留当前版本信息和手动重试按钮。
- APK 下载失败：保留版本提示，允许重试或打开 GitHub 下载。
- 无 JavaScript Pages：页面内容、风格链接和下载链接完整可用，只有轻交互和动画降级。

## 测试设计

### Pages 静态与结构测试

- 断言根页面加九个 `/styles/<slug>/index.html` 共十个独立文档。
- 为每页记录结构指纹：顶级 section 顺序、主要 landmark 数量、交互类型和主布局 class。任意两页不能只有颜色 token 差异。
- 检查十页 release 链接、版本、大小与 SHA-256 一致。
- 检查所有风格导航链接、`aria-current`、焦点顺序和无 JavaScript 可用性。

### Pages 浏览器 QA

- 逐页验证 1440×900、1024×768、375×812、320×700。
- 检查首屏品牌、下一章节提示、长中文、文件名和 SHA-256 无截断与横向溢出。
- 验证十页相互切换、快速连续切换、刷新、前进后退和直接深链。
- 验证正常动效、reduced motion、无 JavaScript和不支持 View Transition 四条路径。
- Apple 页面快速上下滚动时不得出现整屏黑色闪变。
- 控制台无 error/warn，关键 CSS、JS、图标和 404 均返回 200。

### 局域网更新测试

- LAN 高于 GitHub、GitHub 高于 LAN、同版本、单源失败、双源失败和无 APK。
- 自动触发去重、手动强制刷新、服务器切换取消旧请求和同步关闭取消请求。
- 关闭态直接调用 LAN 查询与配对不产生网络请求。
- 桌面目录含无效命名、多版本和修改时间相反的 APK 时，桌面 UI、二维码和 API 始终选择同一个最高规范版本。
- UDP 发现返回真实协议和 APK 版本。
- Android 下载中杀进程恢复、取消、失败重试、未知来源授权和同签名覆盖安装。

### 同步生命周期测试

- 冷启动默认关闭时 REST、WebSocket 和 UDP 调用均为零。
- 在线后关闭会释放 socket、timer、listener 与所有 AbortController。
- 初始 REST、配对、覆盖和 LAN 更新请求中途关闭后不会更新状态。
- 关闭期间的本地修改进入持久队列，重启后仍存在。
- 重开后只有最新 generation 可以连接和确认 mutation。

## 验收标准

- 根路径 Apple 页面滚动过程中没有白到黑或黑到白的整屏突变，reduced-motion 与无 JavaScript同样连续。
- 页面实际存在十份独立 HTML 结构；逐页比较能看到不同的信息顺序、构图、内容表达和交互，不是主题换色。
