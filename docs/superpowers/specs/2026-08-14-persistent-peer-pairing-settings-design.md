# 持久设备配对、连接设置与任务长按动效设计

## 目标

- 长按任务达到阈值后卡片保持上浮，悬浮菜单存在期间不回落；菜单完全退场后再平滑回落。
- 首次设备直连可输入六位码或在格记应用内扫码，对端明确接受后建立持久配对。
- 已配对设备后续发送、接收不再重复输入配对码，但每次完整替换仍由目标设备确认。
- 附近设备列表用双方一致的彩色边框标识配对关系，并支持解除配对和失效后重新配对。
- 恢复点按来源机型分配基础颜色，按创建时间调整颜色强度，便于快速区分。
- 设置首页只展示“连接与同步”总入口，设备直连和电脑同步的详细配置进入各自二级页面。

## 已选方案

### 任务长按

由 `TodayView` 持有 `liftedTaskId`，`TaskCard` 只负责识别长按和展示上浮状态。长按 450ms 后卡片在 220ms 内使用 `cubic-bezier(.16,1,.3,1)` 上浮，随后菜单从触点出现。菜单关闭时先执行约 150ms 退场，`after-leave` 事件到达后才清除上浮状态，卡片使用约 320ms 的非线性缓出回到原位。

菜单业务动作在菜单退场后执行，避免编辑页、删除确认框或路由切换与菜单同时抢占视觉层级。动画只改变 `transform` 和 `opacity`；系统开启“减少动态效果”时将时长降到近乎即时。

### 持久配对

设备直连协议升级为 v2。首次配对使用现有十分钟六位会话码完成身份校验：

1. 发起方选择未配对设备，打开应用内配对浮层。
2. 用户输入对方六位码，或点击“扫码配对”打开应用内相机。
3. 发起方发送 `pair-request`，接收方验证会话码后显示明确的配对请求。
4. 接收方接受时生成 256-bit 随机令牌和一个配对颜色索引，双方在 Android 应用私有 `SharedPreferences` 中按稳定设备 ID 保存同一份关系。
5. 后续 `push-offer` 和 `pull-offer` 使用持久令牌认证，不再接受六位码作为传输认证。
6. 每次完整数据发送或接收仍显示目标设备审批，持久配对只免除重复身份验证，不取消数据替换确认。

配对记录保存对方设备 ID、名称、机型、令牌、颜色索引、首次配对时间和最后使用时间。令牌不进入 NSD/UDP 广播、二维码、Web LocalStorage、业务快照或恢复点。解除配对只删除信任关系，不删除任务和记录。令牌失效时 UI 明确要求重新配对。

协议 v2 不与旧版设备静默互通。发现广播只展示同协议设备，避免旧版被看见后在传输阶段才失败。

### 应用内扫码

Android 使用 `zxing-android-embedded` 的独立扫描 Activity。`DeviceSyncPlugin.scanPeerQr()` 打开应用内相机，只接受 QR_CODE，并把原始文本交给 Web 层现有 URI 解析器再次校验协议版本、IPv4、端口、六位码、设备 ID 和会话 ID。

二维码只包含当前局域网端点和一次性会话码，不包含持久令牌或业务数据。扫描取消、相机权限拒绝和二维码不兼容都返回可理解状态，不自动修改配对记录。

### 附近设备 UI

- 未配对设备显示“配对”，点击后打开配对浮层。
- 已配对设备使用双方一致的颜色边框、色点和“已配对”标签；点击后直接显示发送与接收操作。
- 已配对设备仍需在线才能传输；离线状态保留短暂视觉反馈，不复用旧地址自动连接。
- 配对浮层提供六位码输入、应用内扫码、取消和配对进度。
- 本机可发现卡保留六位码与二维码，隐藏普通用户无须理解的 IP 地址、端口和“复制连接信息”。
- 完全移除“使用地址和配对码”手动连接区块；底层地址解析仅作为二维码协议校验能力保留。

### 恢复点颜色

新恢复点记录 `sourceModel`。颜色由机型或稳定设备 ID 哈希到六个克制的可访问色相；创建时间决定强度：24 小时内为高强度，7 天内为中强度，更早为低强度。旧恢复点没有机型时使用来源名称和设备 ID 计算兼容颜色。

列表使用小色点、轻量内描边和时间标签表达差异，不依赖颜色作为唯一信息。恢复点仍最多保留五份，存储与恢复语义不变。

## 设置页信息架构

设置首页新增一个“连接与同步”大卡片，包含两条可点击入口：

- **设备直连**：显示已配对数量、发现/搜索状态摘要，进入 `/settings/device-sync`。
- **电脑同步**：显示关闭、待配对、在线或待同步摘要，进入 `/settings/computer-sync`。

设置首页不再直接展示发现开关、二维码、服务器扫描、地址和覆盖按钮。两个二级页面都保留底部“设置”Tab 高亮，Android 返回键和页面左上角返回按钮均回到 `/settings`。

设备直连页承载发现开关、搜索、配对设备、二维码、传输操作和恢复点。电脑同步页承载电脑同步开关、服务器扫描、电脑六位码配对、连接地址及“用本机完整覆盖电脑”。版本更新仍留在设置首页。

## 错误与安全边界

- 配对码错误在目标设备弹请求前拒绝，并保留现有限速。
- 配对请求拒绝、超时或断网不会写入半份配对关系。
- 持久令牌不匹配时传输前终止，本机数据不变，并提示重新配对。
- 扫描到其他应用链接、旧协议或非局域网端点时不发起网络请求。
- 接收前恢复点、完整替换、电脑同步暂停和每次目标确认保持原行为。
- 不通过本功能自动合并记录，也不在后台无提示传输。

## 测试范围

### 自动化

- 长按卡片在菜单打开与退场期间保持上浮，`after-leave` 后才回落。
- 协议 v2 二维码生成、解析和旧版拒绝。
- 原生插件包含配对请求、接受/拒绝、令牌保存、解除配对和令牌认证。
- 设置首页只显示连接总卡，两个二级路由拥有正确父级和根 Tab。
- 手动地址区块不再渲染，应用内扫码入口和相机权限存在。
- 恢复点颜色对不同机型稳定、对不同时间桶有区分，并有文字标签。

### 真机

- 首次六码配对、应用内扫码配对、对端接受、拒绝和超时。
- 应用进程重开后配对关系仍存在，双方免码发送和接收。
- 双方已配对边框颜色一致，解除配对后恢复未配对状态。
- 传输仍逐次确认，拒绝不会改变任一端记录。
- 两个设置二级页、返回键、深浅主题、窄屏和减少动态效果。
- 恢复点机型色、时间强度、恢复成功与失败保护。
- 长按任务菜单四角定位、关闭、编辑、专注、排序、删除全路径。

若只有一台 ADB 设备在线，先完成单机扫码、页面、持久化和协议模拟测试，并在第二台重新上线后补齐双真机结论；不得把模拟结果表述为双真机通过。

## 发布

实现和验证完成后升级应用版本，更新 Web、Android、Windows、GitHub Pages 与测试报告；覆盖安装到已连接设备，不卸载、不清数据、不重启。最后提交并推送功能分支和 `main`，发布对应 GitHub Release。
