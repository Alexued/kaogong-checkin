# 格记小红书小工具迁移设计

## 状态与目标

用户已确认新建小工具，不更新平台上现有的「打卡助手」或「考公打卡」。本设计中的题库精简及平台能力降级待确认，确认前不提交平台或修改既有产品行为。

保留格记现有经典视觉、学习任务、计时、宠物和奖励体验。在仓库 minitool/ 中建立专用入口、平台适配、构建、测试及验收文档，Android、Windows 和服务端继续保持现状。

## 方案取舍

1. 推荐：独立小工具构建目标，复用经过测试的领域逻辑和可兼容组件；存储、导航、原生能力及设置页显式替换。方便追踪差异，避免引入完整联网与 Capacitor 依赖。
2. 完全复制网页工程：起步快，但之后宠物、奖励和修复会分叉，维护成本较高。
3. 重写轻量应用：包体小，但容易丢失现有功能和样式，不符合本次迁移目标。

采用方案 1。通过构建期替换和明确的模块边界隔离平台代码，不仅用运行时隐藏按钮掩盖不支持的实现。最终包不得残留被禁能力。

## 目录与职责

- minitool/src：小工具入口、外壳、设置、分享海报、扫码与持久化适配。
- minitool/scripts：构建、资源与兼容性检查、ZIP 打包。
- minitool/test：平台适配、存储与迁移回归测试。
- minitool/docs：功能对应表、验收记录、发布信息。
- minitool/dist：最终静态目录，不提交 Git。
- minitool/release：经过审核的 ZIP 及校验摘要，不混入原 Android release。
- .codex/minitool-zip-builder：用户提供的官方 skill 1.6.0，保留下载来源及摘要，不修改官方脚本以放宽检查。

## 功能范围

### 保留与复用

- 当前源码实际具备的任务、打卡、进度、概览、历史统计、通用/考公模式、背诵及训练流程。
- 11 种宠物、各自已有动画、动作及装扮、食物库存与真实喂养、命名和星星奖励。
- 自定义奖励、原子扣星、待使用与兑换记录。
- 离线心愿券的 P-256 验签、独立身份、请求、签发和重复兑换保护。
- 自制数字键盘的星星小工坊。仅测试构建开放，提交版本默认关闭；正式与测试钱包不得混淆。

历史需求不等于当前已实现功能。按源码逐项建立功能对应表，对尚不存在的功能明确记录，不借迁移名义宣称已实现。

### 平台替代

- 移除电脑/设备联网同步、APK 更新下载、原生安装、Capacitor 生命周期和 Android 插件依赖。
- 使用单页内路由，不依赖服务器路径回退或 ES module 离线加载。
- 使用隔离的 IndexedDB 保存业务数据；读取失败不能默认为新空档并覆盖旧档，写入失败明确反馈。
- 应用与小工具存档不自动互通。不打包个人记录、现有密钥或测试钱包。
- 文件选择只用于图片；JSON/TXT 导入改为页内文本输入与校验。导出展示可选择文本，不调用剪贴板或文件下载 API。容器复制交互须实测，不能保证系统长按菜单可用。
- 扫码改为用户主动授权后的相机预览或选图，通过纯 JavaScript 解码。禁止依赖 Worker、WASM 或原生 ZXing 插件。
- 心愿签名前检测 Web Crypto 和密钥持久化能力；缺失时仅关闭心愿签发/兑换并解释原因，不能以弱签名或免钥匙替代。
- 番茄钟保存时刻和会话状态，返回前台按时间恢复并保持一次结算。不得承诺宿主后台持续执行、锁屏提醒或系统通知。
- 海报与二维码保存调用 saveImageToPhotosAlbum；用户主动分享调用 postNote，图片使用本地 data URI。普通浏览器无桥接时显示预览与说明，不伪造成功。

### 题库精简（待用户确认）

现有 analysis-question-bank.json 有 3988 条，文件 6,803,080 字节。官方 skill 不允许以高压缩率掩盖大型内置数据库问题。

建议首版保留训练与章节功能，按各章节稳定抽样，总量不超过 200 题且静态题库文本预算不超过 512 KiB；保留题目 ID、题干、选项、答案、必要材料和解析，不截断致使题目不可作答。图题仅在所有必要图片可离线随包提供时纳入。界面明确显示「精简题库」和实际题量，不显示完整版题数。

完整版 Android 题库保持不变。不将完整题库改后缀、编码或藏入 IndexedDB 种子以规避审计。

## 构建与兼容

- 单个根目录 index.html，外置经典 JS，无内联脚本、行内事件、module、动态 import、eval 或 new Function。
- 复用现有 Vue 编译链，输出 IIFE，JS 目标 ES2017 / Chrome 61；运行时新 API 单独检测或提供小范围兼容实现。
- CSS 使用 Chrome 61 基线：Flex margin 间距、物理方位属性、基础颜色及尺寸；现代效果仅增强。测试安全区、320px 窄屏、横屏、深色与弹窗键盘遮挡。
- 所有资源离线相对引用。宠物素材优先复用并按显示尺寸压缩，不更换角色风格。
- ZIP 不超过 10 MiB；尽量压到 2 MiB 左右。无 source map、node_modules、构建配置、私有日志和个人数据。

## 验收门禁

1. 现有领域测试回归，小工具专用适配测试、类型及编译检查。
2. 存储首次加载、刷新、写入失败、重复动作；宠物购买/装备/喂养；奖励扣星与使用；心愿正确密钥、错误密钥、重放、取消与余额不足。
3. 页面逐项验收：导航、滚动、长文本、表单、弹窗、亮暗主题、响应式、动画暂停与恢复。
4. 官方脚本审计静态目录及 ZIP；额外检查禁止能力、语法、资源闭合与桥接参数。官方脚本仅是体积辅助检查，不代表完整合规或业务通过。
5. 本地必须通过的测试全部通过后，上传新建格记的包至用户当前小红书创作账号，进行平台预览/体验测试。遇到失败回到修复，不将失败包提交审核。
6. 平台真机相机、存相册、发笔记和旧 WebView 需分别记录。模拟器或模拟桥接不能冒充真机通过。不能完成的项标记未验收，并说明是否阻断提交。

## 上传与 GitHub

新建而非覆盖已有小工具。只上传构建静态包和该工具必要公开资料，不上传用户学习记录、测试心愿、私钥、浏览器凭据或手机数据。

区分上传体验、提交审核及公开发布。记录平台实际状态，不将上传成功描述为审核通过。遇到对外提交确认、必填资料缺失或验证码，按实际页面与权限要求请用户处理。

完成实现及验收后更新根 README 与 minitool 文档，将源代码、构建说明、校验摘要及包校验值提交 GitHub main。不得覆盖已有 APK 发布资源。
