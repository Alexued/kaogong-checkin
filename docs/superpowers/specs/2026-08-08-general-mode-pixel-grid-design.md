# 通用打卡模式与像素动效设计

## 1. 背景与目标

当前应用以考公学习为默认语境。本阶段在不破坏既有任务、打卡、计时、背诵、同步和更新能力的前提下，把产品升级为可切换的通用打卡软件。

本次目标：

1. 提供“通用模式 / 考公模式”切换，旧用户与旧备份默认进入考公模式。
2. 通用模式使用中性的习惯、行动、节律和复盘语言，不暴露百化分、公式、上岸等考公概念。
3. 两种模式共享同一份任务、打卡、计时和设置数据；切换模式不删除、不改写、不复制业务记录。
4. 考公专属背诵记录完整保留，切回考公模式后继续可用。
5. 参考 `afetmin/SwiftPixelGrid` 的 3x3 像素强度、延迟、保持、衰减和 reduced-motion 设计，在 Vue/Capacitor 中实现行为等价的像素动效。
6. 保持离线优先、电脑备份恢复、局域网更新和 Android 原生集成行为稳定。

## 2. 已确认决策

- 技术栈保持 Vue 3、Pinia、Capacitor、Node Server 和 Electron，不引入 SwiftUI 运行时。
- 产品运行时名称与 Android 桌面名称统一为“格记”，包名保持 `com.wjy.kaogong`，避免覆盖安装和历史数据断裂。
- `appMode: 'exam' | 'general'` 是唯一模式状态，写入 v2 设置和 v3 领域设置并参与备份与同步。
- 缺失或非法 `appMode` 一律规范为 `exam`，保证旧数据行为不变。
- 设置页顶部提供两段式模式选择器；模式切换即时生效并持久化，不出现二次确认。
- 通用模式不应用全局 `planEndDate`，但不清空该值；考公模式恢复使用它。
- `markDate` 两种模式共享：考公模式称“考试日”，通用模式称“重要日”。
- 第三个主导航在考公模式为“背诵”，在通用模式为“复盘”。路由保持 `/drill`，避免破坏滑动轨道与 Android 返回规则。
- 通用模式的复盘页复用统计领域函数和图表组件，但使用独立页面语境；考公模式保留原百化分和公式训练。
- 像素动效用于启动、模式切换、倒计时完成和打卡状态反馈，不做无限装饰性背景动画。

## 3. 产品信息架构

### 3.1 通用模式

主导航为：今日、计时、复盘、设置。

- 今日：展示今日节律、连续行动、重要日、今日习惯和未完成结转；支持清单、数量习惯、子项、排序和快速新增。
- 计时：服务于专注、运动、冥想、阅读等通用场景；默认标签示例不再限定为资料分析。
- 复盘：展示连续完成、累计完成日、平均完成率、月度热力、近 14 天节律、计时记录和最近活动日。
- 设置：模式切换、外观、启动动效、数据与电脑连接、更新和版本信息。

通用模式不展示背诵训练、百化分、公式、考试计划结束倒计时，也不把这些历史记录写进活动摘要。考公专属数据继续保存在本地领域状态中。

### 3.2 考公模式

主导航为：今日、计时、背诵、设置。

- 完整保留当前计划、欠账、百化分、公式训练、统计和考试计划能力。
- 计划结束日继续限制任务计划与统计范围。
- 考试日、资料分析和学习记录等语境继续可用。

### 3.3 共享与隔离规则

| 数据 | 两模式共享 | 模式呈现规则 |
| --- | --- | --- |
| 任务、子任务、打卡 | 是 | 文案与示例随模式变化 |
| 计时与计时历史 | 是 | 标签示例随模式变化 |
| 主题、启动动效、电脑连接 | 是 | 无差异 |
| 重要日 / 考试日 | 是 | 同一日期，不同名称 |
| 计划结束日 | 保存但仅考公模式生效 | 通用模式不用于计划或统计截断 |
| 百化分、公式记录 | 保存 | 仅考公模式展示和统计 |
| 当前模式 | 是 | 备份、恢复和同步后保持 |

## 4. 数据模型与迁移

v2：

```ts
type AppMode = 'exam' | 'general';

interface Settings {
  appMode: AppMode;
  planEndDate: string | null;
  theme: 'light' | 'dark';
  markDate?: string | null;
  updatedAt?: string;
}
```

v3：

```ts
interface SettingsV3 {
  appMode: AppMode;
  planEndDate: string | null;
  theme: 'light' | 'dark';
  markDate: string | null;
  startupAnimationEnabled: boolean;
  timerLapFontSize: number;
}
```

迁移和适配规则：

1. v1/v2 缺失字段时写入 `exam`。
2. v2 到 v3、v3 到 v2 双向投影必须保留模式。
3. v3 验证器只接受 `exam` 或 `general`。
4. Pinia 初始值、远端设置合并和快照应用后都必须得到合法模式。
5. 切换只发送一条 settings upsert，不遍历业务集合。

## 5. UI 与视觉语言

采用“生活节律仪表盘”方向：安静、紧凑、适合反复使用。维持现有浅色优先与强调色体系，不把页面变成营销式卡片陈列。

- 设置页的模式选择器位于页面第一信息区，使用明确的分段控件和简短说明。
- 通用模式今日页增加中性状态文案和节律提示，空状态给出喝水、拉伸、阅读等场景启发。
- 通用复盘页保持数据密度，使用全宽摘要带和图表，不嵌套卡片。
- 所有触控目标至少 44x44 CSS 像素；短按钮使用图标或图标加文字。
- 窄屏、横屏、深色模式下文本不溢出、不遮挡；动态内容使用稳定网格尺寸。
- 运行时文档标题和 Android `app_name` 改为“格记”，更新通道、包名和存储键保持兼容。

## 6. SwiftPixelGrid 行为映射

参考仓库固定到提交 `cc194aa84b120b8cb5819bc866c9620cd91481e0`。原项目使用 MIT License，移植说明和归属写入第三方通知。

### 6.1 几何与渲染

- 固定 3x3 网格，按从左到右、从上到下编号 0...8。
- 单元宽 3 个比例单位、间距 1 个比例单位，总几何为 11x11。
- 先绘制低强度 off 层，再按强度叠加 on 层；激活单元可使用受控的 bloom 阴影。
- 组件尺寸通过 CSS 自定义属性缩放，布局盒尺寸在动画期间保持不变。

### 6.2 时间引擎

- 每个单元定义 delay、hold 和 fade。
- 循环长度遵循 `2 * (maximumDelay + duration) + 0.05s`。
- 强度由绝对时间计算，不依赖逐帧累加，页面掉帧后不会产生相位漂移。
- 衰减使用三次贝塞尔 `(0, 0, 0.58, 1)` 的 ease-out 曲线。
- 支持 wave、spiral、pulse 预设，并允许 `active=false` 返回有意义的静态帧。

### 6.3 动效使用

- 启动：像素网格先形成品牌状态，再释放主界面，完整时长不超过 560ms。
- 模式切换：320ms 左右的一次 spiral/wave 过渡，同时更新屏幕阅读器状态，不锁死导航。
- 单次打卡：在触点附近提供一次 320ms 内的像素确认；全天完成才使用较强反馈。
- 倒计时完成：保存面板使用静态或短循环完成状态。
- 控件反馈 120-180ms，页面场景 320-520ms，不使用弹跳式夸张位移。

### 6.4 减少动态效果与性能

- `prefers-reduced-motion: reduce` 时停止 requestAnimationFrame、CSS 循环和 confetti，展示可辨识的静态完成帧。
- 页面不可见时暂停帧循环，恢复后按绝对时间重算。
- 同一屏幕最多一个持续刷新的像素网格；其他实例使用 CSS 静态状态或一次性过渡。
- 动效不改变布局尺寸，不持续分配数组，不触发大面积 layout。

## 7. 可访问性

- 模式选择器使用 `role="radiogroup"` 与 `role="radio"`，公开选中状态。
- 模式切换结果通过礼貌的 live region 宣告。
- 装饰型像素网格 `aria-hidden`；承担状态反馈时使用明确中文标签。
- reduced-motion 下功能和状态信息完整，不依赖颜色或动画表达结果。
- 模式切换后焦点保留在已选按钮，不强制跳转；从通用复盘切回考公时同一路由直接渲染背诵页。

## 8. 测试与验收

自动化测试覆盖：

1. v1/v2/v3 迁移默认值、非法值拒绝和双向适配。
2. 模式计划边界：通用模式忽略 `planEndDate`，考公模式继续应用。
3. 模式切换持久化、同步消息和业务集合不变。
4. 两模式标签、复盘数据过滤和考公训练回归。
5. 像素强度算法、循环边界、静态帧和 reduced-motion 分支。
6. Web 构建、Node 测试、Android Gradle 构建和安装包元数据。

浏览器视觉与动效 QA 覆盖 360x800、393x873、768x1024 和横屏，检查浅色、深色、两模式、键盘和 reduced-motion。

Android 真机测试覆盖所有页面、按钮、分段控件、输入框、列表行、滑动/长按、弹层、确认框、返回键、前后台、强制停止后持久化、旋转、窄屏、深浅色、减少动态效果、离线、电脑连接和更新异常状态。测试期间采集截图、UI 树、logcat、安装包哈希与 `gfxinfo`；最终报告逐项记录步骤、预期、结果和证据。

## 9. 发布与 GitHub

- 目标版本提升到 `0.10.0`，Android `versionCode` 提升到 `13`。
- APK、设备备份、日志和测试工件不提交 Git；测试报告正文存放在忽略的 artifacts 目录，并在提交信息与最终交付中给出路径。
- 实现、测试和报告完成后提交到 `codex/general-mode-pixel-grid`，推送 origin 并创建草稿 PR。

## 10. 非目标

- 不新增账号、云端社交、排行榜、通知打扰或订阅。
- 不为两种模式建立两套任务数据库。
- 不在本阶段重写原生 Android UI 或引入 Swift/SwiftUI。
- 不把像素动效用于背景常驻装饰，不牺牲可访问性和低端设备性能。
