# 离线星星心愿券与隐藏开发者模式

日期：2026-09-07
状态：用户已接受交互方案；本规格待用户审阅后进入实施。
目标版本：0.17.0，Android versionCode 22。

## 1. 已确认的需求

保持经典浅色/深色界面及四个底部入口。在“我的奖励”增加完全离线的奖励分享：送出者定内容与星星价格，接收者收下后，每次兑换都需要送出者给出一次性确认。使用“送出心愿”“收到的心愿”“小钥匙”等文案，避免监督者、被监督者、绑定关系及账户体系。

开发者入口为连续点击“我的奖励”页面标题五次，再通过自制数字键盘输入 192837。可修改星星，不能绕过收到的心愿券所需的送出者确认。

本版完成详细测试、覆盖安装真实手机后，更新 README 并提交到 Alexued/kaogong-checkin 的 main。发布不包含个人存档、设备私钥、真实测试导出或机器配置。

## 2. 范围与取舍

- 主方案：本地二维码承载完整数据，分享一次、每次兑换双向扫码确认。无需互联网、同一 Wi-Fi、热点、蓝牙或账号。
- 不采用固定兑换密码：获得密码后可重复兑换，无法逐次确认。
- 不新增蓝牙或关系管理：避免配对步骤及权限负担。
- 复用已有 ZXing Android 扫描能力，但奖励扫码不得调用附近发现、连接、同步或自动更新流程。
- 复制文本/从本地文件读入同格式数据作为故障恢复入口；不能伪装成短数字密钥，也不强迫用户手输长密文。
- 不控制第三方游戏、电影应用；“已使用”只是本地记录，不代表自动执行现实奖励。

## 3. 用户操作

### 3.1 送出与收下

1. 本人自定义奖励新增“送出心愿”按钮，显示分享前预览：标题、说明、价格、送出昵称。
2. 确认后生成有签名的心愿券二维码，明确标记“离线扫码收下，每次兑换需要小钥匙”。
3. 接收者点“收下心愿”，扫描并看到完整内容、送出昵称和简短来源指纹；点击“收下”才持久化。
4. 相同心愿券重复导入只定位已有卡片，不增加重复条目。
5. 接收者不能更改收到券的价格、名称、来源或确认规则；可隐藏/恢复自己的卡片，不改变原券。
6. 不自动信任二维码上声称的真人身份。首次收券由用户面对面核对昵称/指纹；无在线实名认证承诺。

### 3.2 发起兑换

1. 接收者点“兑换”，核对价格及余额，余额不足时不能发起。
2. 应用保存唯一兑换请求，显示请求二维码和“等一把小钥匙”；此时不扣星、不占用星星、不生成已兑换记录。
3. 同一张券只能有一条待确认请求；返回、刷新、重新打开可继续显示同一请求。用户可取消，取消后该请求的确认失效。
4. 请求包含券摘要、请求随机 ID、接收设备公钥身份及签名。名字不能作为设备唯一标识。

### 3.3 送出小钥匙与完成兑换

1. 送出者扫描请求，验证来源券确由本机签发、奖励未停用且版本未改变，显示奖励、价格、接收昵称及本次请求摘要。
2. 送出者主动点击“送出小钥匙”，本地持久化这次批准，然后展示绑定该请求与接收身份的签名确认二维码。
3. 同一请求重复扫描显示已有批准，不产生新的批准记录；私钥不出现在任何二维码中。
4. 接收者扫描确认，校验签名、券摘要、接收身份、请求 ID 和请求仍待确认，展示最终扣星确认。
5. 点击“确认兑换”时再次检查当前钱包余额和待确认状态，在同一次存储事务内扣星、生成待使用记录、标记请求完成并记录已消费确认。
6. 重复点击、重复扫码、失败重试不能重复扣星。写入失败时不显示成功、不更新内存余额；下次可重试。
7. 等待期间星星被用掉导致余额不足，不扣星，保留请求以便补足后重试；取消则永久终止这条请求。
8. 导航离开、切换沙盒或锁定应用时，不允许旧异步扫码/验签回调写入另一个钱包。

### 3.4 后续修改

- 送出券是本次分享的内容快照。修改原奖励后，需要重新分享新版；旧券请求不得直接套用新版价格批准。
- 停用原奖励阻止本机后续批准。另一台手机离线时不会自动收到改价或撤回信息。
- 已经签发的小钥匙不能远程撤回，批准界面明确提醒；无基于不可信设备时钟的过期承诺。
- 送出者看见“已送出钥匙”，不是“对方已兑换”；不增加第四次回执扫码，也不声称知道另一台手机的余额或兑换完成状态。

## 4. 协议与密钥

- 采用平台 Web Crypto 的 ECDSA P-256 / SHA-256 签名与验证，不自行实现椭圆曲线算法。
- 三种消息使用固定前缀、协议版本和明确类型：心愿券、兑换请求、一次性确认；禁止混用。
- 对固定字段顺序的规范化数据签名，严格验证字段类型、整数价格、长度、枚举、版本、公钥和签名格式。拒绝过大/未知版本/错误类型输入，不当作 URL 打开。
- 随机 ID 使用密码学安全随机源，至少 128 位。券的发行者由公钥指纹识别，确认绑定整张券摘要、请求 ID、接收身份。
- 身份私钥保存在本机独立 IndexedDB 中，优先存为不可导出的 CryptoKey；若平台无法生成或持久保存所需密钥，明确失败，不回退为明文固定通行码。
- 首次使用按需初始化身份；生成与持久化成功后才可出示二维码。身份恢复失败时不得静默重建并冒充旧发行者。
- 沙盒与真实身份分离，测试券带明确测试域；真实钱包不得接受测试域确认。
- 常规宠物导出和分享均不包含私钥或开发者解锁状态。换机导入历史不等于继承发行权或旧接收身份；旧待确认兑换不能在新身份上完成，需重新收券和发起请求。
- 密钥数据不发送网络，不写日志，不纳入仓库。备份回滚、Root、修改应用/存档等对抗行为不在保证范围内。
- 官方接口参考：W3C Web Cryptography API 的 ECDSA 章节；journeyapps/zxing-android-embedded 的嵌入扫描文档。

## 5. 存储、兼容与领域边界

- 现有个人奖励仍按原有方式直接扣星兑换；收到的心愿券是独立受签名约束的数据类型，不能被普通奖励编辑/兑换方法处理。
- 宠物存储 envelope 与导出格式迁移到版本 3；读取兼容旧 v1/v2，旧宠物、余额、装扮、食物、奖励及历史保持不变。
- 同一事务维护共享星星、个人兑换记录、收到券的请求及消费标记；异步签名验证完成后重新检查交易前提。
- 发券快照、签发批准、收券与请求保存于各自钱包的离线心愿子结构，保留稳定 ID 和历史快照。
- 旧档案缺少新字段时初始化为空，不生成虚构收到券或批准。无法识别/不完整的受保护数据拒绝导入，不退化成免确认个人奖励。
- 普通备份导入不得把已经消费的确认重新变为可兑换；同机 envelope 中保留不参与备份替换的追加式消费标记，与钱包扣星在同一次 envelope 写入中提交，导入时核对。该标记不另用一次独立存储写入，以免出现半完成交易。完全回滚全部应用数据仍无法离线防御，应在 README 说明。
- 旧备份导入时显式提醒离线身份不随备份迁移；真实与沙盒读写边界继续保留。

## 6. 可爱但克制的界面

- 保留经典卡片、字号与底部导航；新增心愿券卡片、宠物印章、信封和钥匙图案，不把整套软件换风格。
- 奖励页保留个人奖励与使用记录，增加“收下心愿”和“送出记录”；不建立人际列表或强制关系绑定。
- 请求/确认页始终展示当前步骤、一句操作提示、奖励价格、返回/取消按钮。
- 二维码区域固定白底深色码，四周保留空白，不把宠物图案覆盖在码上；深色主题也保持可扫对比度。
- 完整长度标题/说明采用可读换行；二维码过密或超限应明确提示并提供本地数据替代入口，不静默截断签名内容。
- 320px 窄屏、软键盘、系统导航安全区必须验收；弹窗聚焦和返回关闭行为明确。动画尊重减少动态效果设置。

## 7. 开发者模式

- 仅“我的奖励”页面标题是入口：3 秒内点击 5 次触发，超时重新计数；不因普通导航点击累计。
- 密码 192837 使用应用自制 0–9、删除、清空、确认键盘及六个遮蔽圆点。不得使用可唤起输入法的输入框或自动聚焦文本框。
- 密码错误显示温和提示，连续 5 次错误冷却 30 秒；不声称这是防破解机制。
- 成功后打开星星调节面板，显示“真实钱包”或“测试沙盒”。支持设置为、增加、减少，使用同一个自制数字键盘。
- 余额范围 0–999999999 的整数；禁止负数、小数、溢出，减少不能低于零。
- 提交前显示旧余额、变动、最终余额和操作作用域，并再次确认。失败原子回滚，不累计学习所得星星、不改学习记录。
- 每笔调整记录操作 ID、时间、旧值、新值、作用域；开发者解锁不能批准别人发出的心愿券。
- 解锁仅保留在当前前台会话，应用进入后台、刷新或退出即锁定；本地/备份不保存明文输入或解锁标记。
- 固定密码按用户明确要求提供，属于方便测试的隐藏入口，并非安全秘密。公开源码后更不能宣传为强身份鉴权。
- 发布版包含用户要求的调星入口；原内部测试沙盒与 5 秒番茄捷径仍遵循独立构建开关，不随开发者解锁自动启用。

## 8. 测试与验收

### 自动化

- 正常收券→请求→批准→确认→扣星→使用；个人奖励原路径回归。
- 篡改名称/说明/价格/版本/发行公钥/接收身份/请求 ID/签名；错误类型、未知版本、截断、超长载荷。
- 其他人签的确认、跨券/跨设备/跨沙盒重放、重复导入、重复请求与确认、已取消请求。
- 余额不足、等待时余额变化、双击并发、异步期间切钱包、写入失败和强停重启恢复。
- 原奖励改价或停用之后的旧请求、同一批准重新显示、已批准但未兑换的明确状态。
- 同机导入旧备份不得重复消费，同机身份保存失败、换机身份不匹配、私钥不出现在导出中。
- 开发者 5 次点击时间窗、错误密码/冷却、后台锁定、金额边界、幂等调整、日志及真实/沙盒隔离。
- 保留并运行现有 1240 项回归测试；新增测试数量按实际执行结果报告，不预先承诺数字。

### 设备和界面

- 真机先备份，再覆盖安装；保留学习数据及原番茄时长设置，不清除应用数据。
- 使用独立真实手机/模拟器身份完成离线链路。记录实际设备角色，不把单实例模拟称为双设备实测。
- 关闭 Wi-Fi 和蜂窝数据后验证原生相机扫描；冷启动离线也可生成、解码和验签，无联网下载解码模型步骤。
- 相机权限拒绝、扫码取消、扫错二维码、后台回来、请求恢复均不扣星。
- 320px 窄屏、真实手机、浅色/深色、长文本、键盘不弹出、弹窗和底部栏遮挡、宠物联动逐项留证。
- 测试结束恢复真机测试前网络/主题设置，退出沙盒并锁定开发者模式；任何真实钱包调整只在用户要求的交付设置中发生。
- 尚未验证的横屏、帧率或长期使用等项目明确写入边界，不笼统声称全部场景通过。

## 9. 发布

- 现有工作区包含已验收但未提交的 0.16.0 多宠物改动；本次发布需审查并纳入，不能只提交引用缺失模块的增量文件。
- README 更新宠物、自定义奖励、离线三步扫码、隐藏开发者入口、隐私与离线防作弊限制、安装方法和验收结果。
- 将可公开验收报告放入仓库文档目录；真实存档、相机截图中的个人数据、签名身份文件仅本地保留。公开示例使用生成的测试身份。
- 发布前 fetch origin 并检查差异，验证目标 main 无需强推；如果远程有新提交，先保留并合并其改动，重新测试冲突影响范围。
- 只提交明确属于本次交付的代码、原创素材、规格及文档，不执行 git add 全工作区。
- 代码测试和真机验收完成后再推送 main。APK 如需公开下载使用 GitHub Release 资产，不将二进制强加进源码历史。
- 记录最终提交 SHA、安装包 SHA256、推送结果。未成功推送不得声称已上传。

## 10. 规格自检

- 需求与已批准方案一致：离线双向确认，无固定兑换密钥；192837 仅用于隐藏调星面板。
- 不把“已批准”混为“对方已兑换”；不承诺离线撤销既发确认。
- 扣星与消费标记原子化，调星与学习奖励来源分开。
- 私钥、签名数据、二维码格式实现后必须以异常输入和真实断网测试验证，不能仅凭界面可操作判定通过。
- 已确认不增加账户、蓝牙配对或监督关系管理。本规格没有留空的待定功能。
