# Codex-Claude 功能级融合设计

## 1. 背景与决策

本设计用于 `codex-Claude` 分支。基线是当前仓库的 `main` 提交 `76db0cb`，Claude 参考实现是本地参考仓库的提交 `e8dba753ea55da0c6a10c22254a43dbfd32408aa`，另有一处未提交但不完整的背诵页 XML 修改。

两套实现没有共同 Git 历史，也不是同一架构：

- 当前产品使用 Vue 3、Capacitor Android、Node 服务端和 Electron Windows 伴侣，应用 ID 为 `com.wjy.kaogong`。
- Claude 版本使用 Kotlin/XML 原生 Android 和手机内嵌 NanoHTTPD，应用 ID 为 `com.gongkao.checkin`。

已批准采用功能级融合：保留当前产品的应用身份、数据、同步协议、Windows 伴侣、发布仓库和网页展示，只移植 Claude 版本中可证明有价值的产品能力与算法。不复制 Claude 的整个 Gradle 工程，不改变应用 ID，不引入第二套不兼容的数据和同步协议。

## 2. 目标与非目标

### 2.1 目标

1. 保留现有用户数据并提供幂等、可回滚的数据迁移。
2. 增加数量型任务、单位和逐次进度，同时保留现有逐日可追溯补卡。
3. 将 Claude 的完整资料分析公式和精确百化分判分移植到当前背诵模块。
4. 增加月历、14 天完成率、计时对比和日期记录入口等统计能力。
5. 为 APK 更新增加可验证的 SHA-256 完整性链路。
6. 修复 v0.7.1 真机报告中的返回导航、UDP 自动发现和横屏裁切问题，并针对 120 Hz 卡顿做有测量依据的优化。
7. 保留并扩展现有 Web、服务端、桌面端和 Android 测试体系。

### 2.2 非目标

- 不把 Claude 的原生 Android 工程复制到 `web/android`。
- 不引入 Claude 的四位 PIN、明文宽松鉴权、`/24` 网段 64 线程扫描或手机间 APK 更新协议。
- 不改变 `com.wjy.kaogong`、现有签名链、GitHub 仓库或用户本地存储 origin。
- 不自动发布 Release，不推送远端分支，除非用户另行要求。
- 不把 `.claude/`、`.gradle/`、`.kotlin/`、`app/build/`、`local.properties`、签名材料、安装包或 `artifacts/` 纳入 Git。

## 3. Git 与来源边界

`main` 保持在 `76db0cb`。所有融合修改只发生在 `codex-Claude`。Claude 来源 SHA 写入设计、提交信息和最终变更说明，功能代码按当前仓库模块边界重新实现，不做 unrelated-histories 整树 merge。

Claude 工作树中删除 `fragment_recite.xml` 的 `formulaPreview` 并不是完整修复，因为 `RecitePage.kt` 仍引用该控件。当前产品没有这套 XML/Kotlin 结构，因此不复制该补丁；只吸收其产品意图：背诵首页不显示会泄露答案的公式预览。

## 4. 数据模型与迁移

### 4.1 状态版本

`AppState` 增加整数 `schemaVersion`。当前无版本数据视为版本 1，融合后的格式为版本 2。加载本地状态、接收服务器快照和导入数据时统一调用纯函数 `migrateAppState`，服务器在落盘前也执行相同的结构规范化。

迁移满足：

- 输入对象不原地修改。
- 对同一版本重复执行结果不变。
- 未知字段保留，缺失集合补为空数组。
- 迁移失败时保留原始 `kgc-state`，应用进入只读恢复提示，不用空状态覆盖原数据。
- 成功写入版本 2 前，保留一份仅本机使用的 `kgc-state-v1-backup`；确认新状态可再次解析后才标记迁移完成。

### 4.2 数量型任务

`Task` 增加：

- `target: number`，正整数，默认 `1`。
- `unit: string`，去除首尾空白，最长 12 个 Unicode 字符，默认空字符串。

`Checkin` 从纯二值记录扩展为某任务在某原始日期的进度记录：

- `progress: number`，范围为 `0..targetSnapshot`。
- `targetSnapshot: number`，首次产生进度时从任务目标复制，之后不因任务编辑而改写历史。
- `unitSnapshot: string`，同样保存历史单位。

版本 1 的有效打卡迁移为 `progress=1`、`targetSnapshot=1`、`unitSnapshot=''`；软删除记录保持软删除。`progress=0` 不创建新记录；已有记录降到 0 时沿用软删除语义，保证同步合并和历史兼容。

为避免主任务数量与子任务完成规则互相冲突，第一版明确采用以下约束：

- 有子任务的主任务固定为清单模式，`target=1`，完成状态继续由现有主任务与子任务规则计算。
- 没有子任务的任务可以使用数量模式。
- 给数量型任务新增第一个子任务前，用户必须确认将目标重置为 1；取消则不修改。

### 4.3 结转语义

存储层继续按原始应完成日期保留欠账，不能像 Claude 版本那样把多天欠量压成一条不可追溯记录。今日页可以按任务聚合显示总欠量，但展开后必须列出来源日期；每次增加或减少进度都写回对应原始日期的记录。

聚合顺序为：欠账优先、最早来源日期、任务全局顺序。完成一项后不自动移动到列表末尾，避免操作目标跳动。

## 5. 背诵内容与判分

### 5.1 资料分析公式

以 Claude `FormulaData.kt` 的 36 条、8 个分类为内容来源，转换为 TypeScript 结构：

- `key` 保持稳定，用于历史 `formulaKey` 关联。
- 字段包含分类、名称、公式、条件和提示。
- 公式渲染继续使用当前 Web 组件，不引入原生 `FormulaView` 语法。
- 全部背诵按固定源顺序；随机背诵继续使用当前会话与历史机制。
- 分类筛选只改变题目集合，不删除或重写历史记录。

### 5.2 百化分

以 Claude `PercentData.kt` 的 24 项为参考数据。判分使用整数交叉相乘，接受约分前后的等值分数和明确登记的近似答案；分母为 0、无法解析、溢出或额外字符均判错并显示可读提示。

交叉相乘先校验为 JavaScript 安全整数；超出安全范围时使用 `BigInt`。不再用浮点容差决定分数是否相等。测试覆盖负号、零分母、等值分数、近似答案和超大整数。

## 6. 统计体验

现有设置页中的 30 天概览保留，独立统计页扩展为以下可扫描区域：

1. 连续天数、全勤天数、平均完成率、距计划结束日四项摘要。
2. 可前后翻月的月历热力图；点击有记录的日期进入日期详情。
3. 固定 14 天、包含缺席日的完成率柱图，纵轴固定 0% 到 100%。
4. 最近 12 条未删除计时记录的用时对比，标出平均值和最快记录；倒计时记录与秒表记录分组，避免不同目标混在一条比较轴上。
5. 最近 14 个有记录日期的摘要列表，可进入日期详情。

图表使用当前 Vue/CSS/SVG 能力实现，保持键盘可访问、文本替代和深浅主题。图表容器有稳定高度，加载、空状态和标签变化不能导致页面跳动。`prefers-reduced-motion` 下取消柱形入场和月历切换位移。

## 7. 更新完整性与版本

版本目标为开发中的 `0.8.0`、Android `versionCode 11`。版本号由单一 JSON 清单提供给 Web、Android、server、desktop 和发布脚本；构建校验发现任一消费者不一致时失败。

CI/本地发布校验生成 `release-manifest.json`，至少包含：

- `version`
- APK 文件名
- 字节数
- SHA-256
- applicationId

检查 GitHub 更新时，客户端优先读取 GitHub asset 的 `digest`；没有 digest 时读取同一 Release 的 `release-manifest.json`。下载完成后、调用系统安装器前必须计算本地文件 SHA-256：

- 摘要一致才允许继续安装。
- 摘要不一致立即删除下载文件并显示“文件校验失败，可重新下载”。
- Release 没有任何可信摘要时，保留浏览器下载入口，但应用内下载按钮标记为不可校验并不直接安装。
- LAN APK 继续使用服务端已计算的摘要，并走同一个验证器。

## 8. 四项真机问题

### 8.1 返回导航 `BACK-001`

不再依赖 `window.history.state.back` 判断二级页。路由为二级页面声明明确父入口：

- 日期详情返回 `/settings`。
- 任务管理返回 `/`。
- 计时历史和详情返回 `/timer` 或上一级计时历史。

Android 返回键、页面内返回按钮和浏览器历史统一调用同一导航函数。只有四个 Tab 根页才调用 `minimizeApp()`。回归测试覆盖深链冷启动、正常进入、页面内返回和系统返回。

### 8.2 UDP 自动发现 `DISC-001`

保留现有 8321/8322 和 v2 鉴权协议。桌面/服务端枚举活动 IPv4 网卡并向每个网卡的定向广播地址发送发现包，同时保留全局广播作为兼容路径；Android 监听绑定所有接口并在扫描窗口内去重。

诊断日志记录脱敏后的网卡名、绑定端口、接收计数和解析失败原因，不记录令牌、配对码或完整用户数据。自动发现失败时继续提供手动地址，不启用 Claude 的高并发 `/24` 扫描。

### 8.3 横屏裁切 `ORIENT-001`

继续支持旋转，不通过强制竖屏规避。浮动按钮和底部导航使用逻辑方向安全区、视口约束和固定触控尺寸；在小高度横屏时主要操作进入紧凑布局，任何固定元素的边界不得超出视觉视口。

验收覆盖报告中的 `818 x 360` CSS 视口、360 px 窄屏、键盘弹出和旋转恢复。

### 8.4 120 Hz `PERF-001`

先用原报告相同操作采集基线，再根据浏览器 Performance 和 `adb shell dumpsys gfxinfo` 定位。优化仅针对测得热点：避免对大面积元素使用昂贵滤镜，滚动处理合并到单一动画帧，列表更新保持稳定 key，原生 WebView 中禁用无收益的整页 View Transition。

发布门槛不是“没有长帧”这一弱条件，而是同设备、同场景下 janky frame 比例相对 v0.7.1 的 35.33% 明显下降，且 P99 不回退。最终报告同时给出绝对值和采样条件，不把未测状态写成已修复。

## 9. 同步与兼容性

新增字段沿用现有 last-write-wins 和离线队列。服务端状态校验、REST 全量覆盖、WebSocket upsert、桌面读取和导出都必须认识版本 2 字段。旧客户端连接版本 2 服务端时，协议握手返回最低客户端版本；不允许旧客户端用缺字段快照覆盖版本 2 数据。

电脑同步关闭时，新增功能仍只能写本地状态，不得启动 REST、WebSocket、UDP、更新自动检查或重连。重新开启后先迁移本地队列，再握手同步。

## 10. 错误处理与隐私

- 迁移、导入或服务器快照校验失败：保留原数据和队列，展示恢复入口，不静默清空。
- 公式或百化分内容异常：跳过单条并记录开发日志，其他练习仍可使用。
- 图表数据为空：显示稳定尺寸空状态，不伪造数据。
- UDP 不可用：降级为手动地址，不自动扫描整个子网。
- APK 摘要失败：删除损坏文件，不启动安装器。
- 任何日志、测试夹具、报告和提交不得包含真实 Cookies、令牌、配对码、Local Storage 或设备私有备份。

## 11. 测试与验收

### 11.1 自动化

- Web：状态 v1 到 v2 迁移、幂等性、数量进度、逐日欠账、聚合展示、公式内容、百化分精确判分、统计计算、返回路由和更新摘要。
- Server：版本 2 状态校验、旧客户端保护、定向 UDP 广播、关闭资源释放和摘要接口。
- Desktop：版本清单一致性、APK 选择与摘要暴露。
- Android：下载后 SHA-256、校验失败删除、返回策略和取消恢复。
- 现有全部测试继续通过，Web 和 Android 构建成功。

### 11.2 视觉与交互

- 桌面浏览器与 360 x 800、393 x 852、818 x 360 视口检查今日页、任务编辑、背诵、统计、更新和错误状态。
- 检查浅色、深色、`prefers-reduced-motion`、键盘导航和 200% 字体缩放。
- 不允许文字重叠、固定控件越界、图表跳动或返回路径丢失。

### 11.3 真机

- 在保留真实数据备份的前提下覆盖安装开发包，确认 applicationId、签名和升级前后状态摘要一致。
- 回归 v0.7.1 报告全部用例，特别是 `BACK-001`、`DISC-001`、`ORIENT-001` 和 `PERF-001`。
- 同步测试使用隔离服务端目录；结束后恢复用户原始数据、正式服务和显示设置。

## 12. 完成条件

只有同时满足以下条件才可宣称功能级融合完成：

1. `main` 未改变，工作分支为 `codex-Claude`。
2. Claude 高价值能力按本设计进入当前架构，没有并存第二套应用。
3. v1 数据可无损迁移、重复迁移稳定、同步双方理解 v2 schema。
4. 自动化测试和构建通过。
5. 目标视口视觉验收通过。
6. 真机四项问题有重新采集的证据；未通过项如实保留，不得以代码存在代替验证。
7. Git 状态只包含预期源码和脱敏文档，不包含私密 `artifacts/` 或构建产物。
