# 设备直连同步与应用内确认框设计

## 1. 目标

在不依赖电脑或互联网的情况下，让手机和平板在同一局域网内进行一次性完整记录传输，并将删除任务等场景使用的 Android 原生确认框替换为格记自己的可访问确认面板。

本阶段包含：

1. “允许附近设备发现本机”和“主动搜索附近设备”两个独立开关。
2. 局域网设备发现、手动地址与六位配对码、二维码深链三种连接方式。
3. “发送本机记录”和“接收对方记录”两个明确操作。
4. 每次传输都要求目标设备确认。
5. 接收前自动创建恢复点，校验后完整替换，失败时不改变本机数据。
6. 设置页提供恢复点列表和恢复操作。
7. 使用统一应用内确认框替换现有 `window.confirm`。

本阶段不包含云中继、跨互联网同步、后台常驻发现、自动无感合并、逐条冲突解决、iOS 实现或无需用户确认的持续设备同步。

## 2. 已选方案

### 2.1 原生 Android NSD 与本机 TCP 服务

新增项目内 Capacitor 原生插件 `DeviceSyncPlugin`：

- 使用 Android `NsdManager` 注册和发现 `_kgc-sync._tcp.` 服务。
- 使用动态本机 TCP 端口承载长度前缀 JSON 协议。
- 设备发现和主动搜索由插件统一管理，避免与现有电脑 UDP 发现端口冲突。
- 服务只在应用前台且“允许被发现”开启时存在；进入后台后停止注册、关闭监听端口并取消等待请求。
- 主动搜索只在应用前台且对应开关开启时运行。

未选择纯 UDP 分片传输，因为完整快照、审批等待、重试和错误回执都需要可靠有序连接。未选择 Wi-Fi Direct 或 Wi-Fi Aware，因为当前目标明确限定为同一局域网，额外权限和设备兼容成本没有必要。

### 2.2 设备直连独立于电脑同步

设备直连是一次性完整替换，不进入电脑同步的 last-write-wins 合并过程。

- 传输开始前暂停电脑同步网络生命周期。
- 接收成功后将电脑同步总开关设为关闭，并保留服务器地址和配对令牌。原待同步队列随恢复点归档，活动队列清空，避免旧本地变更在重新开启电脑同步后污染已接收快照。
- UI 明确提示：“已暂停电脑同步，防止电脑中的旧快照覆盖刚接收的数据。”
- 用户可以稍后手动重新开启电脑同步，并决定是否先将当前数据备份到电脑。
- 发送记录不会改变发送方的电脑同步开关。

## 3. 术语与用户语义

- **允许被发现**：本机在格记前台时可被同一局域网中的格记设备看到，并能收到传输请求。
- **主动搜索**：本机搜索当前局域网中的可发现格记设备。
- **发送本机记录**：将本机完整记录提供给对方，对方确认并创建恢复点后完整替换。
- **接收对方记录**：请求对方提供完整记录，本机确认并创建恢复点后完整替换。
- **恢复点**：完整替换前的本机不可变快照，最多保留最近五份。
- **完整替换**：收到的数据成为全部本地业务状态，不按更新时间合并，也不保留接收快照中不存在的记录。

## 4. 发现、连接与配对

### 4.1 正常发现

NSD 服务只广播非敏感信息：

- 协议版本
- 稳定设备 ID 的短指纹
- 用户可读设备名
- 应用版本
- 当前服务端口

任务标题、统计数量、配对码、令牌和快照摘要不进入发现广播。

主动搜索结果按稳定设备 ID 去重，忽略本机。设备离线或停止被发现后，从列表中进入“已离线”短暂状态，再移除，避免列表抖动。

### 4.2 手动地址与配对码

可发现设备显示：

- 当前局域网 IPv4 地址与端口
- 本次可发现会话的六位配对码
- 复制连接信息按钮

六位码在每次重新开启“允许被发现”时重新生成。连续错误尝试按来源地址限速。关闭开关、应用退到后台或会话超时后，旧码立即失效。

### 4.3 二维码

可发现设备使用已有 `qrcode` 依赖生成二维码。二维码包含：

- 自定义深链版本
- 主机地址与端口
- 设备 ID
- 会话随机数
- 六位配对码

二维码不包含业务数据。另一台设备使用系统相机扫描 `kgc://peer-connect?...`，Android 将深链交给格记，格记进入设置页并预填连接信息。深链参数必须通过协议版本、地址、端口、设备 ID 和长度校验，不能直接触发数据传输。

## 5. 传输协议

### 5.1 帧格式

TCP 连接使用四字节大端长度加 UTF-8 JSON 帧。单帧和完整快照均有明确大小上限，超过限制立即拒绝。

公共消息字段：

- `protocolVersion`
- `requestId`
- `kind`
- `sourceDevice`
- `targetDeviceId`
- `createdAt`
- `pairingCode`

业务快照使用现有 v3 `StorageEnvelopeV3`，外层增加：

- `transferFormatVersion`
- `snapshotSha256`
- `snapshotUtf8Bytes`
- `summary`

### 5.2 发送本机记录

1. 发送方生成 v3 快照、摘要、字节数和 SHA-256。
2. 发送方先发送 `push-offer`，不发送业务快照。
3. 对方插件验证配对码、设备 ID、协议版本和限速。
4. 对方应用显示传输审批面板。
5. 对方拒绝时返回 `rejected`，连接关闭。
6. 对方同意后创建本地恢复点，并返回 `ready`。
7. 发送方发送快照帧。
8. 对方插件写入临时文件，核对字节数和 SHA-256，再交给 Web 层验证 v3 领域结构。
9. Web 层原子替换本地状态，完成后返回 `committed`。
10. 两端显示成功摘要。

### 5.3 接收对方记录

1. 本机先显示“本机记录将被完整替换”的应用内确认面板。
2. 本机发送 `pull-offer`。
3. 对方显示“是否允许向此设备发送记录”的审批面板。
4. 对方同意后生成并校验快照，再发送给本机。
5. 本机创建恢复点、校验 SHA-256 和 v3 领域结构，然后原子替换。
6. 任一阶段失败时，本机原数据和恢复点目录保持可用，不写入部分状态。

## 6. 恢复点与原子替换

### 6.1 恢复点存储

原生插件将恢复点写入应用私有目录 `files/device-sync-recovery/`：

- 临时文件写完并 `fsync` 后 rename 为正式文件。
- 元数据包含来源设备、创建时间、快照摘要、字节数和 SHA-256。
- 最多保留五份，只有第六份成功写入后才删除最旧文件。
- 恢复点不通过设备直连或电脑同步再次传播。

### 6.2 应用替换

新增单一入口 `replaceLocalStateFromPeer()`：

1. 等待现有本地持久化完成。
2. 解析并验证 `StorageEnvelopeV3`。
3. 暂停电脑同步和发现生命周期。
4. 调用 Store 的完整快照替换。
5. 将 v3 repository、兼容 `kgc-state` 和空活动同步队列作为同一逻辑事务提交；替换前的队列写入恢复点元数据。
6. 任一写入失败时从刚创建的恢复点恢复，并将应用置为需要恢复状态，不允许空状态覆盖原数据。

恢复操作复用相同校验和替换入口，但会先为“恢复前当前状态”再创建一个恢复点，从而允许撤销一次恢复。

## 7. 设置页信息架构

新增独立的“设备直连”区块，放在“电脑同步”之前：

1. 顶部状态：设备名称、仅限同一 Wi-Fi、前台可用说明。
2. 两个独立开关：
   - 允许附近设备发现本机
   - 主动搜索附近设备
3. 被发现开启后显示本机连接卡：地址、六位码、二维码和剩余会话时间。
4. 搜索开启后显示附近设备列表：设备名称、平台、应用版本和在线状态。
5. 点选设备打开操作面板：
   - 发送本机记录
   - 接收对方记录
   - 查看连接详情
6. 空结果等待完成后显示“没有发现设备”，并提供：
   - 使用地址和配对码
   - 显示/扫描二维码说明
7. 恢复点入口显示最近一次接收前备份和“查看全部”。

“正在搜索”必须显示真实加载状态，不能提前闪现空结果。所有网络状态保留最后一次设备列表，并以刷新状态覆盖，不用空白卡片替换已有结果。

## 8. 应用内确认框

新增全局 `AppDialogHost` 和 Promise 化 `confirmDialog()` 服务，替换全部七处 `window.confirm`。

确认框分为三类：

- `neutral`：电脑备份等非破坏性操作。
- `warning`：退出训练、数量目标转清单等可理解但有影响的操作。
- `danger`：删除任务、删除计时记录、清空背诵记录、完整替换和恢复。

视觉与交互：

- 竖屏手机使用底部确认面板，横屏和平板使用居中卡片。
- 标题先说明动作，正文明确数据影响，按钮使用具体动词，不使用笼统“确定”。
- 危险操作取消按钮获得初始焦点，危险按钮不自动聚焦。
- 支持 Android 返回键、遮罩点击、键盘 Escape、焦点圈定和 `role="alertdialog"`。
- 同一时间只显示一个确认框，后续请求排队。
- 减少动态效果下只淡入，不执行位移。
- PixelGrid 只用于操作完成反馈，不在等待用户决定时循环播放。

首批替换范围：

- 删除任务
- 删除计时记录
- 电脑备份
- 退出百化分训练
- 清空百化分记录
- 退出公式训练
- 添加子任务导致数量目标重置
- 设备发送、接收、恢复和覆盖审批

## 9. 错误处理

- 多播被访客 Wi-Fi 阻断：保留手动地址、配对码和二维码路径。
- IP 地址变化：已发现条目失效并提示重新搜索，不复用旧端点。
- 对方离线：显示“设备已离线”，本机数据不变。
- 配对码错误：不弹出目标审批面板，按来源限速。
- 对方拒绝：显示明确拒绝状态，不自动重试。
- 协议或数据版本不兼容：在传输前拒绝并提示升级另一端。
- 快照摘要不一致：删除临时文件，保留恢复点和原状态。
- 应用退到后台：停止发现并取消尚未批准的请求；正在提交的本地原子替换完成后再进入后台状态。
- 网络中断：不应用部分快照，不把失败请求记录为成功。
- 自己连接自己：按稳定设备 ID 拒绝。

## 10. 测试策略

### 10.1 纯逻辑与 Web 测试

- 连接码、深链和地址解析。
- v3 快照摘要和数量摘要。
- 完整替换前后恢复点调用顺序。
- 电脑同步暂停语义。
- 对话框队列、取消、危险按钮文案和 Android 返回优先级。
- 设置页两个开关独立性、搜索加载/空/成功/错误状态。

### 10.2 Android 单元与集成测试

- NSD 注册、发现、去重、停止和生命周期 generation。
- TCP 长度帧、超限、超时、错误 JSON 和摘要不一致。
- 配对码轮换、错误次数限制、应用后台取消。
- 恢复点原子写入、最多五份和读取校验。
- 深链 Intent 解析。

### 10.3 真机测试

- 两台 Android 设备在同一 Wi-Fi：发现、配对、发送、接收、拒绝、超时。
- 广播不可用时：手动地址与二维码。
- 发送前后各模块数量和抽样记录一致。
- 接收前恢复点可恢复，恢复后再次可撤销。
- 传输中断、电量优化、横竖屏、深浅主题、减少动态效果。
- 所有原生确认框调用均不再出现 Android 系统样式。
- 最终 crash buffer、logcat、内存和长时间开关压力检查。

若测试环境只有一台连接到 ADB 的真机，则使用本机 Android 服务端加桌面协议模拟器覆盖双端协议，并明确记录二维码和第二台实体设备测试缺口，不伪造双真机结论。

## 11. 成功标准

- 两个开关能够独立开启和关闭，离开前台时网络资源全部释放。
- 搜索结果可以选择发送或接收，扫描失败时仍可通过连接信息或二维码连接。
- 每次传输都经过目标设备审批。
- 接收和恢复都执行完整替换，不发生自动合并或删除记录复活。
- 接收前恢复点可验证并恢复。
- 电脑同步不会在接收后立即覆盖设备直连结果。
- 现有七处 `window.confirm` 全部移除。
- Web、Android 构建和自动化测试通过，真机无崩溃、ANR 或数据残留。
