# 移动端同步控制与本地覆盖设计

## 目标

让移动端用户明确控制是否与服务器同步，并提供一次性“本地覆盖服务器”操作。关闭同步时，移动端完全离线；开启同步时，首次连接仍按现有规则先读取服务器，再重放本地离线队列。

## 交互

- 设置页新增“上传同步”开关，默认开启以保持现有用户行为。
- 开关关闭后立即停止 WebSocket、取消重连，并且不再请求服务器快照；本地状态和离线队列继续持久化。
- 开关打开后重新执行同步启动流程：先加载本地缓存，再拉取服务器快照，最后按序重放本地队列。
- 同步开启且在线时显示“用本地覆盖服务器”按钮。点击后必须二次确认，确认内容明确说明服务器现有数据将被本地完整状态替换。
- 覆盖成功后清空已经提交的本地队列，保留本地状态，并提示成功；失败时保留队列并提示原因，不能静默丢数据。

同步开关和本地覆盖操作不写入 `settings`，只存储在移动端 `localStorage`，避免被服务器快照覆盖。

## 数据流

### 关闭同步

`stopSync()` 关闭 WebSocket、清理重连定时器、标记同步未启动。Store 的本地变更仍然乐观应用并写入本地状态和离线队列，但不会发送网络请求。

### 开启同步

`startSync()` 保持现有顺序：本地缓存水合 -> 请求服务器快照 -> 应用服务器快照 -> 重放队列 -> 建立/保持 WebSocket。服务器不可达时进入离线状态，不删除本地数据或队列。

### 本地覆盖服务器

客户端调用 `PUT /api/state` 提交当前完整 `AppState`。服务器校验集合结构后原子写入 `server/data/data.json`，并向其他 WebSocket 客户端广播 `{ kind: "snapshot", state }`。覆盖成功后客户端清理本地队列并应用服务器返回的快照。

服务器替换是单次操作，不改变普通 WebSocket 消息的 last-write-wins 规则。请求失败、数据校验失败或写盘失败时返回错误，服务器保留原状态。

## 服务端接口

- `GET /api/state`：保持现有行为。
- `PUT /api/state`：请求体为完整状态对象；验证 `tasks`、`subtasks`、`checkins`、`timers`、`drills`、`formulaDrills` 数组和 `settings` 对象存在后替换状态。
- 写入沿用现有临时文件 + rename 和 `.bak` 备份策略。
- `snapshot` 广播只供客户端刷新，不进入离线上传队列。

## 客户端模块

- `api/sync.ts`：增加同步开关状态、`stopSync()`、重连定时器清理、快照事件处理和覆盖服务器方法。
- `stores/app.ts`：增加对服务端快照事件的应用入口；本地 `send()` 行为保持不变。
- `types.ts`：补充全量替换请求和快照事件类型。
- `views/SettingsView.vue`：增加开关、在线状态、本地覆盖按钮、确认和成功/失败反馈。
- `api/client.ts`：增加 `replaceState()` REST 客户端方法。

## 错误与边界

- 关闭同步期间不创建新的网络连接，也不执行启动时 `GET /api/state`。
- 关闭同步前已发送的消息可能已经落盘；重新开启时仍按服务器 last-write-wins 规则处理。
- 覆盖操作期间禁用按钮，避免重复请求。
- 覆盖失败不清空队列；覆盖成功才清空队列。
- 服务器收到非法状态返回 400，不修改现有数据。
- 现有服务端旧客户端收到 `snapshot` 时忽略，不影响普通消息同步。

## 验证

- 客户端构建：`cd web && npm run build`。
- 服务端接口：验证 `PUT /api/state` 成功替换、非法请求返回 400、写盘失败不破坏原数据。
- 同步行为：关闭同步后不产生 `/api/state` 请求；重新打开后先拉快照再重放队列。
- 覆盖行为：本地缺失的服务器记录被删除，其他客户端收到快照并刷新。
- Android 打包：`npx cap sync android` 后执行 `gradlew assembleDebug`。
- 更新发布：递增版本号，创建 GitHub Release 并上传 APK；移动端“检查更新”可发现新版本并打开 APK 下载链接。
