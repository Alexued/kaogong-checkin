# v0.13.0 数据恢复、设备直连与 Opus5 融合设计

## 目标

解决 v0.12.0 在真实新设备上的两项阻断问题：旧数据备份存在但手动恢复仍失败；局域网设备已发现并配对，却在用户未明确拒绝时返回“对方已拒绝”。同时审阅 `F:\Claude\GongkaoCheckin` 的页面、动效和交互逻辑，选择性融合到格记，而不是整体换皮。

## 方案选择

### 数据恢复

首次自动迁移继续严格校验，任何异常都进入只读保护。只有用户点击“验证并恢复”时，才允许为历史孤儿打卡、计时和子任务补建已归档的“已恢复的历史项目”。原始迁移备份保持逐字节不变，恢复失败时继续保持只读，并显示稳定错误码、原因和下一步操作路径。

不采用自动删除孤儿记录或清空重建。两者都会让界面恢复可写，但会破坏用户历史，且无法满足“原始数据未被覆盖”的承诺。

### 设备直连

入站“允许接收”和“允许发送”均使用显式决策弹窗。遮罩、Escape 和 Android 返回键只消费返回动作，不转换成拒绝；只有“拒绝本次”按钮会发送 `REJECTED`。Android 短暂 `onPause` 时停止主动发现以节电，但保留用户明确开启的接收服务和当前连接；用户关闭开关或应用销毁时再释放。

不采用自动接受传输。完整替换属于高风险数据操作，目标设备每次确认仍是不可省略的安全边界。

### Opus5 选择性融合

采用连续底栏指示条：位置直接绑定页面拖动进度，手指拖动时跟手，点击标签时用 320ms 强调缓出曲线落位。保留格记已有页面常驻、滑动视差、PixelGrid 状态动效和任务卡分组入场。控件按压统一为 160ms 快速缓出，减少动态效果时近乎即时切换。

不采用 Opus5 的大面积蓝紫渐变、任务彩色侧条、玻璃庆祝层、大卡片低密度布局，以及忽略系统设置的强制触觉反馈。格记的视觉目标是明亮、克制、信息密度优先；动效负责解释状态和页面连续性，不负责装饰。

## 验收

1. 含孤儿历史关系的旧备份可手动恢复，原备份字节不变。
2. 设备确认只能由两个可见按钮完成，返回键和遮罩不会误拒绝。
3. 开启“允许附近设备发现本机”后，短暂系统暂停不会关闭接收端或当前请求。
4. 底栏指示条在拖动、点按、宽屏和减少动态效果模式下位置正确。
5. Web、Server、Desktop、Android 单元测试和构建通过，并在不清数据的真机上增量安装回归。
