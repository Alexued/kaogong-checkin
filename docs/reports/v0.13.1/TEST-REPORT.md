## 4. 双 Android 设备直连

### 4.1 互搜与版本广播

| 用例 | 结果 |
| --- | --- |
| 两端冷启动后互搜 | 双向发现成功 |
| Android 12 连续五次关闭/重开搜索 | 五次均成功，`73–117ms` 发现 Android 13 |
| Android 13 连续五次关闭/重开搜索 | 五次均成功，`43–71ms` 发现 Android 12 |
| 对端版本显示 | 两端均为 `v0.13.1` |
| 系统 mDNS 丢失兜底 | 应用 UDP 广播 + 1 秒探测 + 单播响应成功恢复发现 |
| 最终运行错误 | `FATAL EXCEPTION`、NSD/UDP 启停错误、解析超时均为 0 |

修复策略：

1. 等待旧 NSD 会话的停止回调后再重开，并用 generation 隔离迟到回调；OEM 不回调时使用 2 秒有限兜底。
2. 过滤本机自身及重复 NSD 广播，串行解析并在失败时有限重试。
3. 每次托管使用带会话后缀的唯一服务名，避免 Android 缓存把旧端口和新配对码组合。
4. 保留 NSD，同时增加不含配对码或记录的 UDP 元数据广播；搜索端每秒探测，托管端向探测源单播响应。
5. TCP 建连对瞬时 `EHOSTUNREACH` / `IOException` 使用两次短退避重试。
6. 广播版本直接读取应用唯一 `APP_VERSION`，不再回退到硬编码 `0.12.0`。

残余风险均不阻断本版本：

- APK 为历史 Debug 签名，只适合当前 `internal-debug` 更新渠道，不作为应用商店正式签名。
- 本轮覆盖当前同一 Wi-Fi 与两台 Xiaomi Android 设备；应用层 UDP 探测已覆盖系统 mDNS 丢失，但其他厂商系统和启用客户端隔离的路由器仍可能需要地址、配对码或二维码备用路径。
- 本轮按用户要求未重启手机，因此没有执行“设备重启后自动恢复开关”的系统级场景；应用冷启动、进程重建和多次覆盖安装已执行。

本报告只记录实际执行的测试，不把未执行场景写成已通过。
